# 性能指标

[English](performance.en.md)

本文件定义并给出16上下文产品在理想原生接口下的任务延迟、稳态吞吐率和计算单元忙率：二摘要压缩538周期/任务，4096元素哈希274434周期/任务；共享模乘的稳态有效发射率分别为87.7323%与88.0591%。

一个 COMPRESS2 任务对两个四元素摘要置换一次，一个 HASH 任务哈希一条域元素消息。rate8 是块宽，不是每拍元素数；16上下文保存共享一颗置换核的在途任务状态。

## 测试条件与复现

产品配置状态12元素、rate8、摘要4元素、16上下文、最大4096元素。输入在合法且ready时连续提供，摘要和完成出口持续ready，enable保持开启；不引入外部带宽限制。内部真实队列、信用和反馈等待全部保留。通过 [验证脚本](../tools/verify.py) 与独立C/Python参考逐项核对；完整命令见 [快速复现](reproduction.md)。

孤立延迟测试2个任务，前一任务外部完成后才提交下一个。连续压缩提交128任务，剔除启动与排空，取完成排序中第16和第112任务之间的96个完成间隔；连续HASH提交64任务，取第16和第48之间的32个间隔。此处序号从0开始。两次连续运行要求全部性能统计一致。

## 指标定义

令任务控制握手周期为 $A$，该任务首输入握手为 $F$，摘要外部握手为 $O$，完成握手为 $C$：任务延迟 $L=C-A$，摘要延迟 $O-A$，首输入至摘要 $O-F$。孤立延迟不受同时在途任务影响；空HASH没有 $F$。

令 K 为两个采样完成时刻 C0、C1 之间的完成间隔数，n 为每任务输入域元素数（本页为8或4096）。稳态任务吞吐率 $T=K/(C_1-C_0)$（任务/周期），等效平均任务间隔 $1/T$。它由连续完成事件测量，不由孤立延迟取倒数。换算频率 $f$ 时，任务/秒为 $fT$，输入元素/秒为 $nfT$，延迟秒为 $L/f$。上述换算不是板级或硅后实测。本页500 MHz换算对应 [综合摘要](synthesis-summary.md) 的综合配置。

## 忙率定义

W 为统计窗口周期数，N_issue 为有效发射数，N_occupied 为至少一级有效的周期数，N_slots 为有效“阶段、周期”对的数量。验证层逐周期直接观察有效工作，计数不进入产品SV。有效发射率 $U=N_{\mathrm{issue}}/W$；空闲周期为 $W-N_{\mathrm{issue}}$。流水线任一级有效的周期比例为 $N_{\mathrm{occupied}}/W$；阶段平均占用率为 $N_{\mathrm{slots}}/(dW)$，其中 $d$ 为流水线深度。`io_busy` 不用于算术忙率。统计窗口取对应稳态任务最终置换返回事件之间的核心周期，避免把后续任务计入窗口。
